# gpu04: one GLM-5.3 base replica moves to the long tier (3 base + 1 long)

File: `prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V12Q8-gpu04-3B1L.yaml`, generated by `scripts/prepare_glm53_gpu04_3b1l.py`.
Rollback file: `prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V12Q8.yaml` (what gpu04 runs today, v0.0.541).

## Why

Since gpu13 left the GLM long tier on 2026-11-03, gpu23 is the only long host (4 TP2 replicas, 64 running).

OpenRouter gateway, per 24 h window ending 21:33Z:

| Window | Long served | Long `backend_queue` 429s | Base `long_reserve` 429s |
|---|---|---|---|
| 10-31 | 185K | 36 | 21K |
| 11-01 | 161K | 431 | 24K |
| 11-02 | 220K | 198 | 43K |
| 11-03 | 179K | 25K | 51K |
| 11-04 | 72K | 21K | 0 |

The number of long requests has stayed flat at about 160-220K a day since 10-30, so demand didn't change; what we lost was capacity. OpenRouter's router backs off providers that 429, and that's why long traffic fell on 11-04.

The change moves one base TP2 replica to long:
- long: 64 → 80 running slots (+25%);
- base: 512 → 448 running slots (−12.5%).

Over 11-03 and 11-04, base at p95 ran about 235 of 256 slots per host.

## What changes on gpu04

| | Before | After |
|---|---|---|
| GPUs 0-5 | base r1-r3 | unchanged |
| GPUs 6-7 | base r4 | `model-sg-glm53-w4afp8-tp2-l4`: gpu23's r2b (v12 image `da8d4e4b5ec6`, Q8 prefill, 16K chunks, 16 running, HiCache 325 GiB), with `--max-queued-requests 32` instead of 8 |
| `proxy-glm53` | pools r1-r4 | pools r1-r3 |
| `proxy-glm53-long` | none | pools l4 |
| nginx | `:8000`, `:8444` | adds `:8001` (see below); the base TLS vhost becomes `default_server` |
| registrar | `ip:8000` on the base domain | adds `ip:8001` on the long domain |

nginx `:8001` serves:
- `/v1/models`: a synthetic `z-ai/glm-5.3-flash-long` stub, gated on `proxy-glm53-long`;
- `/healthz`, `/v1/metrics` and chat: proxied to `proxy-glm53-long`.

A new TLS vhost sends the `glm-5-3-flash-long.*` names, including `-long-i<N>` and `-long-b<hex12>`, to `proxy-glm53-long`.

Registrar details:
- Both endpoints register with routing port 8444, and the canonical id is never registered under the long domain.
- The long endpoint has its own health check and failure count.
- The old one-shot `unregister :8001` is removed.

**Why queue 32:** the OpenRouter gateway applies one long-host ceiling (56) to every long host. A host counts as saturated at 16 queued (`VLLM_PROXY_ADMISSION_QUEUE_SATURATED_AT`). With a queue of 32, l4 is steered around at 16 queued, before the engine would refuse. With gpu23's queue of 8 it would answer 503s first.

**Model-proxy sharing:** both domains share one model-proxy backend (`ip:8444`), as gpu23 does with `LONG_TIER_ONLY=false`.
- An unregister of either endpoint briefly drops the backend from both domains. The registrar only does that after 3 consecutive failures.
- If `proxy-glm53-long` is down, the `:8001` stub returns 5xx, so discovery drops only the long domain.

Checked locally (2026-11-04):
- The nginx config passes `nginx -t`.
- A live SNI test with stand-in proxies: base names, base `-b` handle and `gpu04.hosts.near.ai` → `proxy-glm53`; long names, `-long-b` and `-long-i` → `proxy-glm53-long`; `:8001/v1/models` → the stub; with the long proxy stopped, `:8001/v1/models` → 500 and `:8000` unaffected.
- The registrar script passes `sh -n` in its curl image.
- All CI validators pass.

## Deploy (gpu04 `b4938c50-08f3-4635-a209-512ac69a4000`, merged main tag only)

Every call:
- takes an explicit `services` list;
- runs with `dry_run: true` first;
- checks that `plan.remove` is empty and that the plan touches only the listed services.

A dry-run `up` can start missing containers, so read the plan before anything else.

1. **Pre-check:**
   - `docker/ps` shows r1-r4 up;
   - the version shows `prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V12Q8.yaml`;
   - the v12 image is already on the host (r1-r4 run it).
2. **Free GPUs 6-7:** `compose/down` with `services: ["model-sg-glm53-w4afp8-tp2-r4"]`. This cuts r4's in-flight requests, as any replica recreate does. `proxy-glm53` (old pool) marks r4 unhealthy and keeps serving r1-r3.
3. **Start the long replica and its proxy:** `compose/up` with `services: ["model-sg-glm53-w4afp8-tp2-l4", "proxy-glm53-long"]`.
   - Ready means l4's `/health` is 200 in its log and `docker/ps` shows it Up.
   - Nothing routes to it yet.
4. **Drain gpu04, then switch routing:**
   - `compose/down` with `services: ["model-proxy-registrar"]`. Its SIGTERM handler unregisters gpu04, so model-proxy and the OpenRouter gateway stop sending new requests.
   - Wait until gpu04 `proxy-glm53` in flight is about 0, with a 10-minute cap.
   - Then `compose/up` with `services: ["proxy-glm53", "nginx", "model-proxy-registrar", "otelcol-contrib"]`, `force_recreate: false`.
   - This is the only step that touches gpu04's base path.
5. **Verify:**
   - `/backends/list?domain=glm-5-3-flash-long.completions.near.ai` lists the gpu04 handle healthy, and the base domain still lists gpu04.
   - Over TLS with verification, `https://glm-5-3-flash-long-b<handle>.completions.near.ai/v1/models` and the base handle both answer `z-ai/glm-5.3-flash`.
   - The signing address on the long path matches the base path.
   - A 1-token chat completion succeeds on each path.
6. **OpenRouter gateway (cvm-ansible-playbooks):** append the long backend URL and probe `http://160.72.54.198:8001` to the long lists. Set budget 472 → 504 and long reserve 56 → 88 (gpu23 56 + gpu04 l4 32). That keeps the base allowance at 416, with a 208 bound per base host. Deploy only after step 5.

## Watch (24 h)

- Long `backend_queue` and `host_share` 429s on the gateway.
- Base `long_reserve` 429s.
- l4 queue depth and TTFT against gpu23's replicas.
- gpu04 base running and queued.

**Stop and roll back** if base `long_reserve` 429s go above the 10-30/31 level (about 600 a minute) for a sustained period.

## Rollback

1. Gateway first: drop the gpu04 long entries, and set budget back to 472 and reserve back to 56.
2. Then on gpu04:
   - `compose/down` with `services: ["model-sg-glm53-w4afp8-tp2-l4", "proxy-glm53-long"]`;
   - redeploy the V12Q8 file with `services: ["model-sg-glm53-w4afp8-tp2-r4", "proxy-glm53", "nginx", "model-proxy-registrar", "otelcol-contrib"]`.
