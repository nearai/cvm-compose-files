# GLM-5.3 Flash P/D qualification on one drained base host

`prod/GLM-5.3-Flash-SGL-PD-W4AFP8.yaml` (generated by `scripts/prepare_glm53_pd_qualification.py`) runs prefill/decode (P/D) disaggregation on **one drained base-tier host**. It defines no registrar, nginx or inference proxy, so the host takes no production traffic while it runs. Load arrives only through `glm53-pd-relay`, a TLS relay that uses the same scheme and `PROXY_TOKEN` as `glm53-soak-relay`.

The goal is to find whether a P:D ratio beats colocated 4×TP2 (v0.0.466), and which ratio (3P:1D or 1P:3D), for base-tier and long-tier traffic. It runs on an HGX/NVSwitch host. On the lab's H200 NVL hosts, CUDA IPC between NVLink islands corrupts KV, which limited the lab to 2P:2D.

## Lab evidence (gpu31/gpu32, CC off, 2026-10-03/04)

- **GPU→GPU KV over NIXL/UCX CUDA IPC needs all three of these:**
  1. Every engine sees all 8 GPUs, each pinned with `--base-gpu-id`.
  2. `pid: host`.
  3. `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:False`.

  With all three, SGLang's scattered 35K × 64 KB transfer runs at 18 GB/s, and a cached 189K-token turn takes 0.45 s instead of 6–11 s. With expandable segments on, the transfer silently falls back to host staging at 0.3 GB/s.
- **Fixed-step EAGLE (3 steps / 4 draft tokens) instead of `--speculative-adaptive`**, with decode at mf 0.84, grows the decode KV pool from 383K to 1.64M tokens. GSM8K 98.7%.
- **Island-local 2P:2D vs colocated, normal mix (3/5/7 req/s):**

| | Colocated | 2P:2D |
|---|---|---|
| TPOT p90 | 26/78/148 ms | **16/17/13 ms** |
| TTFT p90 | **1.0/1.6/2.0 s** | 4.6/11.3/31.3 s |
| Unserved | 1/16/74 | **0/0/0** |

  2P:2D was prefill-bound: only 2 of 4 replicas do prefill.
- Full write-up: Notion "P/D disaggregation on SGLang v0.5.21: base tier".

## What the file changes vs the base file

- **Image:** stock `lmsysorg/sglang:v0.5.21-cu130`. It includes #39340, the DSA multi-chunk prefill fix.
- **Start-up patches** (`configs: glm53_pd_startup_patch`), applied by exact anchor and fail-closed:
  - the W4AFP8 `modules_to_not_convert` loader fix;
  - the 8192 default thinking budget;
  - pinned P/D metadata buffers. Under HCC/PPCIe, UCX's cuda_copy transport calls `cuMemHostRegister` on pageable host memory, and the CVM rejects it (`NIXL_ERR_BACKEND` at aux registration, gpu03 2026-10-06). Buffers allocated with `cudaHostAlloc` (torch `pin_memory`) skip that call. `UCX_TLS=^cuda_copy` is not an alternative: NIXL refuses any `UCX_TLS` without `cuda_copy` or `cuda`.
- **Not carried:**
  - HiCache: upstream uses `cudaHostRegister`, which fails with CUDA error 801 under HCC/PPCIe.
  - The admission reserve and the DSA indexer query split: these are fork patches.

## Gates, in order (stop at the first failure)

0. **Topology:** the GPUs must be HGX/NVSwitch, i.e. `NVIDIA H200`, not `H200 NVL`. DCGM reports `NVIDIA H200` on gpu02/03/04/13/23.
1. **CC transfer path:** bring up 1P:1D as `pf-r1` + `dc-r2` with a router. Pass if:
   - startup logs are clean (no 801, NCCL, Xid or OOM);
   - a cached 189K-token turn takes under 1.5 s;
   - GSM8K(150) through the relay is at least 95%.

   If CUDA IPC fails under PPCIe, stop: P/D is not viable on CVMs today.
2. **Ratio sweep:** run 3P:1D and 1P:3D, then optionally 2P:2D. Each arm runs:
   - GSM8K(150);
   - base-tier load: the prefill-heavy mix at 2/3.5/5 req/s and the normal mix at 3/5/7 req/s;
   - long-tier load: synth `--tier long`.
3. **Baselines on the same host:**
   - `prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8.yaml` engines plus `glm53-soak-relay`, for the base tier;
   - `prod/GLM-5.3-Flash-SGL-TP4-W4AFP8-LongContext.yaml`, for the long tier.

## Procedure

Same orphan rule as `docs/glm53-tp2x4-base-canary.md`: compose-manager runs `up --remove-orphans`.

1. **Drain.**
   1. `compose/down` the current base file with `services: ["model-proxy-registrar"]`. Note that dashboard `compose/down` ignores `dry_run`.
   2. Unregister the endpoint and confirm the peers list one fewer backend.
   3. Stop `proxy-glm53` as well. cloud-api placement routes on the inference proxy's replica-state reports, so a host with a live proxy keeps getting traffic after the unregister (gpu03, 2026-10-06).
   4. Wait for `num_running_reqs` to reach 0.
2. **Stop the base engines** with a scoped `compose/down` of the four `tp2-r*` engines, `proxy-glm53` and `nginx`.
3. **Bring up a layout.** `compose/up` this file with the layout's services, plus `glm53-pd-relay`, `otelcol-contrib` and `dcgm-glm53`. Dry-run first.

| Layout | Services |
|---|---|
| 3P:1D | `pf-r1`, `pf-r2`, `pf-r3`, `dc-r4`, `pd-router-3p1d` (relay :8008) |
| 1P:3D | `pf-r1`, `dc-r2`, `dc-r3`, `dc-r4`, `pd-router-1p3d` (relay :8009) |
| 2P:2D | `pf-r1`, `pf-r3`, `dc-r2`, `dc-r4`, `pd-router-2p2d` (relay :8010) |

   - Switch layouts with a scoped `compose/down` of the engines that leave. A GPU pair must never run two engines at once.
   - Engine metrics are at `:8011/m/<engine>/metrics` and in Grafana under `deployment="glm53-flash-sgl-pd-qual"`.
4. **Roll back.**
   1. `compose/down` this file's services.
   2. `compose/up` `prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8.yaml` at the currently deployed tag, with the full service list including `model-proxy-registrar`.
   3. Check the peers list two base backends again.
