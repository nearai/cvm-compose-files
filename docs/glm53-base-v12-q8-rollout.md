## Rules

- **At most 2 base replicas down fleet-wide, and never two on the same host.** A replica that is down for any reason counts. Check `docker/ps` and `/backends/list` on gpu03 and gpu04 before every step.
- **Off-peak only:** start a step only when base load is under ~45 running per replica (mean `sglang_num_running_reqs` over the base replicas, last 15 min). Peak runs about 52 of 64. Cold start under CC is about 20-22 min.
- **`dry_run: true` first, every call.** The plan must recreate exactly the one listed service. If it shows anything else (`model-downloader`, `proxy-glm53`, nginx, the registrar, another engine, orphan removals), stop.
- **Explicit `services` list of one replica on every call.** No `compose/down`, no KMS step, no env-map changes. Never kill a running `compose/up`. If gpu-manager cuts the stream at 5 min, poll `docker/ps`; if the replica is absent or `Created`, re-send the same scoped `up`.
- Tell Henry before the canary and before each host's first fleet step, with the replica and the time.
- The long tier is not part of this rollout (it already runs v12 + Q8).

## Sequence

Every step is `POST http://<host>:8080/compose/up` with:
- `tag`: the merged tag, older than `MIN_TAG_AGE_HOURS`;
- `file`: as below;
- `services`: `["model-sg-glm53-w4afp8-tp2-rN"]`;
- `env`: the host's existing full env map;
- `force_recreate: false`.

Send it with `dry_run: true`, check the plan, then send the same call with `dry_run: false`. Ready = `/health` 200, `/backends/list` shows the replica ready, and it serves traffic.

1. **Canary: gpu04 r4.**
   - `file: prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-Q8Canary.yaml`.
   - Run the gpu04 pre-check above first.
   - Bake (5-minute checklist), then reads at **2 h, the next peak, and 24 h**: r4 against gpu04 r1-r3, which stay v7.
   - Go to step 2 only after the 24 h read passes.
2. **gpu04 r3 -> r2 -> r1**, one at a time, `file: prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V12Q8.yaml`. Each gets the 5-minute bake before the next starts.
   - r4 needs no redeploy: the canary's r4 equals the fleet's r4 (tested).
   - The canary file and the fleet file differ only in r1-r3 and the aggregator/collector config, which this sequence replaces.
3. **gpu04 host step** after r1 bakes green:
   - `services: ["glm53-ghost-aggregator"]` (now v12);
   - then `services: ["otelcol-contrib"]` with `force_recreate: true`;
   - both from the fleet file, dry run first, plan = that one service.

   Until then the collector keeps scraping each replica by `server_address`; only the `engine_image` / `config_variant` values lag.
4. **Read gpu04 (all v12) against gpu03 (v7, r4 v8)** at **2 h and the next peak** before touching gpu03.
5. **gpu03 r1 -> r2 -> r3 -> r4**, one at a time, `file: prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V12Q8.yaml`, each with the 5-minute bake. Then run the gpu03 host step, the same as step 3.
6. **Fleet 24 h read.**

## Bake and reads

**5-minute bake after every replica.** Use the checklist in `docs/glm53-v7-fleet-rollout.md` ("5-minute bake"):
- ready and routed;
- dashboard populated;
- clean logs;
- serves production traffic;
- TTFT p95 / ITL p95 against the unmigrated peers;
- neighbours untouched.

Its startup-line check changes for v12:
- `docker ps` shows the `da8d4e4b5ec6…` digest;
- the server args show `dsa_prefill_backend='flashmla_sparse_q8'`, `dsa_decode_backend='flashmla_kv'`, `kv_cache_dtype='fp8_e4m3'`, `chunked_prefill_size=8192`, `max_queued_requests=32`, `enable_hierarchical_cache=False`, `disable_overlap_schedule=True`.

**Reads (2 h, next peak, 24 h).** Compare against the v7 replicas over the same window, at matched running. While the labels lag, filter by `host_machine` and `job="sglang-<service>"`, not by `engine_image`.
- TTFT p50/p95/p99 (`sglang_time_to_first_token_seconds`) and ITL p50/p95 (`sglang_inter_token_latency_seconds`);
- served requests and prompt/generation tok/s; running and queue depth;
- queue-full rejections (`The request queue is full.`) and gateway `backend_queue` rejections; 5xx;
- prefill/decode step time from `Prefill batch` / `Decode batch` log windows;
- `docker inspect -f '{{.RestartCount}}'` stays 0; no `Traceback|CUDA error|Xid|out of memory|NCCL` in the logs.

The lab predicts (not a gate): TTFT p50 down 10-30%, decode per stream up 5-15%, served req/s up 5-9% at saturation.

## Abort and rollback

- **Abort a step, and roll back that one replica**, on:
  - an engine exit or restart, Xid, CUDA error or OOM;
  - free memory under 2 GiB for 5 minutes;
  - a preprocess-pool timeout storm;
  - not serving within the bake.
- **Latency:**
  - **Canary:** a latency miss is recorded but is not an automatic rollback. Step 2 waits until it is understood.
  - **Fleet steps:** TTFT p95 or ITL p95 more than 20% worse than the v7 peers over the bake stops the lane and rolls that replica back (the v7 rollout's criterion).
- **Rollback = `compose/up` of that one service, same tag, `dry_run` first:**
  - Every base replica except gpu03 r4: `file: prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8.yaml` (v7).
  - gpu03 r4: `file: prod/GLM-5.3-Flash-SGL-TP2x4-W4AFP8-V8KdaCanary.yaml`, to restore exactly what it ran (v8 KDA). The v7 file also works but drops KDA.
- If the host's aggregator and collector were already recreated, recreate them from the v7 file too, the same way as step 3.
- The 2-down / one-per-host limits apply to rollbacks. A cause shared across replicas (the image) stops the whole rollout.

## Evidence

**Source:** tee-bench **exp 53**, branch **`exp53-glm53-base-fp8-load-ladder`** (`exp53-README.md`; cells named `e48*` on gpu31).

**Setup:**
- gpu31 bare metal, two isolated TP2 lanes, n=2 lane-swapped rounds;
- driver `replay_with_raw_gaps.py`, prod mix, 600 s;
- arms differ only in the image and the prefill backend token, on the base prod argv.

**v12q8 against v7:**

| Load | Result |
|---|---|
| 0.5 conv/s (below capacity, 0 shed) | TTFT p50 -12/-14%, E2E p95 -10/-9%, decode per stream +9/+5% (served by both) |
| 1.0 conv/s (saturated) | served req/s +7.7/+5.6%, shed -1.5 pp, output tok/s +10/+7%, decode +12/+7%. Served by both: TTFT p50 -31/-27%, E2E p95 -12/-11%. |
| 1.5 conv/s | served req/s +5.6/+4.7%, total tok/s +8.5/+11.6%, E2E p95 -6/-7% |
| 2.0 conv/s | served req/s +8.5/+5.0%, decode +13/+15%, E2E p95 -8/-4% |

At 1.5 and 2.0, TTFT follows the lane, not the arm; read it only against the A/A cells.

**Other results:**
- Quality: GSM8K-100 0.99 (v12q8) vs 0.98 (v7). Smoke: 0 fatal, no new failures.
- Queue 64 lost to queue 32 (TTFT ≤ 10 s attainment fell in all four comparisons), so **queue stays 32**.
- Earlier: exp 46c (v10 + Q8 against v7, 1.0 conv/s) showed the same direction; Q8 with 16K chunks hurt base decode, so **chunk stays 8192**.

**Pending at preparation:**
- the A/A noise floor (`e48aa*`);
- the prod-shaped `prodbase` mix cells;
- the lever cells (EAGLE 3/1/4, chunk 4096).

The argv change here is limited to the image and the prefill backend.

## Caveats

- **Bare-metal lab, CC off.** The TDX/PPCIe tax is not reproduced, so the prod deltas may be smaller. The canary is the first CC measurement of v12 on the base argv.
- **Chat template snapshot.** gpu31 ran `84c6a6…` (lab) in both arms; prod uses `3f1971b…` (this file's `--chat-template`). The arms are comparable with each other but differ slightly from prod.
- **v12 bundles more than Q8:**
  - v8 zero-sync KDA (neutral on bare metal, exp 45b; on gpu03 r4 in prod since 10-12);
  - the v11 K-pool indexer logits budget (-2.9% inside the A/A, exp 47);
  - CVE pins.

  The exp 53 delta is the bundle, not Q8 alone.
- **Smoke crashers C08/C09/C10/C12 were skipped on v12 in the lab** (as in 46c), so v12's behaviour on those inputs is unmeasured on the base argv. Prod exposure depends on whether the gateway clamps or rejects those inputs before they reach an engine. Confirm the gateway clamps with Route/Ops before the fleet steps. Note that the long tier has served the same image since #385.
- **The lab mix is harsher than prod base:** 17% of lab requests are 32-64K against 1.6% in prod, and 56% are cached against 75%. Absolute lab numbers are pessimistic; only the arm deltas carry over.
