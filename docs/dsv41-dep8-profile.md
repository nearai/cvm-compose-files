# DS4.1 DEP8 in-CVM kernel profile (Profile pack)

`prod/DeepSeek-V4.1-Flash-1017-vLLM-DEP8-Abliterated-Profile.yaml` is the DEP8 file plus a one-shot torch
profile. Generated by `scripts/prepare_dsv41_lora_dep8.py` (layout `DEP8_PROFILE`); the normal DEP8 and
DEP4x2 files are unchanged. **One host only, for one measurement; not a standing prod file.**

## Purpose

A prod DEP8 replica in a TDX+PPCIe CVM runs a ~50 ms decode round at near-zero prefill, against ~31 ms on
bare metal (TEE stays). One kernel profile taken inside the CVM splits that round into TEE host overhead,
NCCL, MoE and attention, and the boot log shows which transport NCCL chose.

## What differs from DEP8

Same image digest, argv, env, models, proxies, nginx and registrar, except:

- each of the 8 ranks gets `--profiler-config '{"profiler":"torch","torch_profiler_dir":"/traces",...,"ignore_frontend":true}'`
  (no stacks, no shapes) and the shared volume `dsv41-traces` at `/traces`;
- `NCCL_DEBUG=INFO` and `NCCL_DEBUG_SUBSYS=INIT` instead of `NCCL_DEBUG=WARN` (boot log lines show P2P/CUMEM vs SHM/NET);
- service `dsv41-profiler` (engine image, host network, no GPU, `restart: "no"`) running
  `scripts/dsv41_profile_summary.py`, embedded as the compose config `profile_summary`;
- nginx `location ~ ^/(v1/)?(start|stop)_profile { return 403; }` in all four server blocks (8000-8003);
- `config_variant` carries a `-profile` suffix, so its metrics are separable from prod; the deployment name is DEP8's.

## What the profiler service does

1. Waits until all 8 ranks answer `GET http://127.0.0.1:910<N>/health` with 200, then sleeps `PROFILE_DELAY_S`
   (default 900) so real traffic is flowing.
2. Deletes old files in `/traces`, `POST /start_profile` to all ranks in parallel, sleeps `PROFILE_DUR_S` (default 3),
   `POST /stop_profile` to all ranks (timeout 600 s). No retry. Then waits (up to `PROFILE_SETTLE_S`, default 120 s)
   until every rank's trace file exists and its size is unchanged across two checks 2 s apart.
3. Parses `dp<N>_*.pt.trace.json.gz` per rank (GPU kernel, memcpy, memset events). Drops events within +-60 ms of any
   `sm90::prefill` kernel on any rank (ranks aligned by `baseTimeNanoseconds`). Fails if a rank file or
   `baseTimeNanoseconds` is missing.
4. Prints one JSON line per rank (`rank`, `window_ms`, `decode_window_ms`, `busy_ms`, `categories`, `memcpy`,
   `top_kernels`, `allgatherv_us`, `prefill_intervals`), then `{"profile_done": true, "ranks": 8}`, deletes the traces
   and exits 0. On any error it prints one `{"profile_error": "..."}` line (the only error output) and exits 1. After
   any failure following the first `/start_profile`, it also sends a best-effort `/stop_profile` (10 s timeout, errors
   ignored, in parallel) to every rank that was sent a start and not yet stopped, and deletes the traces, so a failed
   run leaves neither a running profiler nor traces on disk.

## What leaves the CVM

Only the container stdout of `dsv41-profiler` (Loki): kernel-name aggregates and timings, no prompts, request data or
raw trace content. Raw traces exist only in the `dsv41-traces` volume inside the CVM and are deleted on success and on failure. The
rank ports 9100-9107 are on the CVM host network and are **not** in the CVM port map, so `/start_profile` and
`/stop_profile` are not reachable from outside; the nginx 403s are defence in depth for the public path
(`location /` -> proxy -> rank). Whether the vllm-proxy-rs build pinned here forwards arbitrary paths to a rank was
not verified (no source access), hence the denies.
The deny covers only the public edge: anything else on the CVM host network can still reach 127.0.0.1:9100-9107 and
thus the profile routes (low risk).

This host's compose hash differs from the standard DEP8 pack, so a deploy reviewer must not treat it as the standing
prod measurement.

## Deploy on one host and revert

Deploy mechanics belong to Ops. Constraints from this repo:

- Use this file on **one** host (the profiling target); every other host keeps the normal DEP8 file.
- All files on a host share the `dstack` project. The Profile file has the DEP8 service set plus `dsv41-profiler`,
  so switching from DEP8 only adds a service, and switching back removes it (intended).
- To measure, `up` the Profile file; all 8 ranks and the proxies pick up the changed config. The profiler fires once,
  `PROFILE_DELAY_S` after the ranks are healthy; read the lines from the `dsv41-profiler` logs.
- To revert, `up` the normal DEP8 file (same deployment name, no `-profile` suffix). Optionally remove the
  `dsv41-traces` volume.
- To re-profile without a redeploy, recreate only `dsv41-profiler` (scoped `up`, force recreate).

## Expected restart cost (estimate, not measured here)

Changing argv and env recreates all 8 ranks, so the host drops out of the pool for a full engine boot, twice (once
into the Profile file, once back). The registrar deregisters after 3 failed probes. Gpu31 lab numbers for DEP8 weight
load are ~45 s with `OMP_NUM_THREADS=8`; kernel-cache, graph capture and DP start-up add to that. Ask Ops/Bench for
the measured CVM boot time before scheduling. The profile adds `PROFILE_DELAY_S` (15 min) after health, and a
3 s capture on live traffic.
