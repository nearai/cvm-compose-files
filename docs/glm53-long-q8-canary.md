# GLM-5.3 Flash long-tier Q8 + 16K-chunk canary: ONE long TP2 replica (r2b)

Status: **prepared, not deployed; blocked on the v9 image digest.** Merging changes no running service. The canary file is generated only after `glm53-hicache-w4afp8-v9` is published (`V9_IMAGE_DIGEST` in `scripts/prepare_glm53_long_q8_canary.py`), and the host changes only when an operator deploys the merged tag to it, scoped to the one service below, through the already-running compose-manager.

## What changes

| | r2b (canary) | other long TP2 replicas (controls) |
|---|---|---|
| image | **v9** `glm53-hicache-w4afp8-v9` = v8 + `dsa-q8-flashmla-sparse.diff` (flag-gated) | v7 `sha256:fa730e6e…` |
| `--dsa-prefill-backend` | **`flashmla_sparse_q8`** | `flashmla_kv` |
| `--chunked-prefill-size` | **16384** | 8192 |
| decode backend, environment (incl. `SGLANG_DSA_INDEXER_QSPLIT=1`), GPUs, queue/running caps, HiCache | long v7 fleet, unchanged | long v7 fleet |
| `engine_image` / `config_variant` labels | v9 digest prefix / `...-q8-c16384` | unchanged |

v9 also carries v8's zero-sync KDA (#352), so r2b differs from the controls by three things: Q8 prefill kernel, 16K chunks and zero-sync KDA. The KDA patch is neutral on bare metal and is being read separately on the base tier (#354).

File: `prod/GLM-5.3-Flash-SGL-TP4-W4AFP8-LongContext-Q8Canary.yaml`, generated by `scripts/prepare_glm53_long_q8_canary.py` from the long fleet file. `scripts/test_glm53_long_q8_canary.py` asserts that only r2b's image, the two argv flags and its telemetry labels differ, and that r2b keeps the DSA indexer split (required with 16384).

## Lab basis (tee-bench exp 45b long block; bare gpu31, CC off, TP2, same v7 long argv as the fleet)

Long workload `b64_100k,b100_256k`, 0.09 conv/s, 600 s, admission reserve off as on the fleet. Lane-swapped cells:

| arm | cells | completed req | total tok/s | TTFT p50 / p95 | >64K TTFT p95 | e2e p50 / p95 | TPOT p95 | longest gaps (p95) |
|---|---|---|---|---|---|---|---|---|
| v7 | 3 | 130 | 17,206 | 7.2 / 38.1 s | 40.8 s | 29.1 / 83.7 s | 96 ms | 634 ms |
| Q8 + 16384 | 2 | 186 (+43%) | 21,435 (+25%) | 2.5 / 27.5 s | 31.8 s | 27.2 / 83.2 s | 149 ms | 1,056 ms |

Uncached prefill tok/s is equal (9.4K vs 9.0K). The gain is shorter prefill queueing, so turns complete sooner at the same offered load; it is not more raw prefill capacity. The cost is the decode tail. GSM8K-100 0.90-0.91 on both (the long-argv baseline), and there were no engine errors.

**Known prod risk.** The 2026-09-25 TP4 canary ran chunk 16384 (no Q8, tilelang prefill, v6 image) and regressed TTFT p95 1.62x over 4 h. This candidate differs in topology, kernel and admission setting, but **TTFT p95 vs the same-host controls is the first abort criterion.**

## Rules

- **One replica out of the pool, fleet-wide.** No other base or long replica may be down or recreating when r2b is recreated. At most 2 base replicas down at any time; long-context replicas one host at a time.
- **Tell the team (Henry) before the deploy**, with the host, the replica and the time.
- **Do not overlap other canaries.** If the base v8 KDA canary (#354) is mid-read, wait for its decision.
- `compose/down` is never used, and a running `compose/up` is never interrupted.

## Build and deploy

1. Merge the recipe PR; run `publish-glm53-admission-reserve.yaml` with variant `hicache-w4afp8` (default tag `glm53-hicache-w4afp8-v9`); take the pushed digest.
2. Put the digest into `V9_IMAGE_DIGEST` and add the v9 image to `W4AFP8_QSPLIT_CAPABLE_IMAGES` (plus any long-context image allowlist) in `scripts/validate_glm53_prod_config.rb`. Run `python3 scripts/prepare_glm53_long_q8_canary.py --write`, the test, and the validator. Merge.
3. Bare smoke of v9 with the canary argv on a lab host: boot, GSM8K-100, the smoke gate (`RUN_SMOKE=1`), one 600 s long replay.
4. On the chosen long host only: compose-manager `POST /compose/up`, with `tag` = the merged tag, `file: prod/GLM-5.3-Flash-SGL-TP4-W4AFP8-LongContext-Q8Canary.yaml`, `services: ["model-sg-glm53-w4afp8-tp2-r2b"]`, the host's existing full `env` map, and `force_recreate: false`.
   - Send `dry_run: true` first. The plan must recreate exactly that one service.
   - Then `dry_run: false`. Poll `docker/ps` until r2b shows a NEW container `Up N minutes` on the v9 image. If it is left in `Created`, re-send the scoped `up`.
   - Ready = `/health` 200, `/backends/list` shows r2b ready, and it serves traffic. A cold start under CC is about 20 minutes.

## Bake and reads

Use the 5-minute bake checklist from `docs/glm53-v7-fleet-rollout.md`. The controls are the other long TP2 replicas over the same window, with the same-host replica first.

Reads at 2 h, at the next peak and at 24 h, r2b vs controls, by prompt bucket (64-128K, ≥128K):
- TTFT p50 / p95 / p99, and ITL p50 / p95 at matched running;
- e2e p50 / p95, and completed requests per minute at matched offered load;
- prefill pass time and pass rate from `Prefill batch` log windows;
- queue depth, queue-full rejections, 5xx;
- served prompt and generation tok/s.

**Success:** TTFT p95 at least 10% better than the controls with no regression in served tok/s or 5xx; ITL p95 regression ≤ +60% (the lab cost).

**Abort (roll back r2b only):**
- TTFT p95 more than 10% worse than the controls;
- any Xid / CUDA error / OOM / engine exit, or a `Q8 KPool topk width` ValueError;
- retraction or 5xx above the controls;
- ITL p95 more than 2x the controls.

## Rollback

`compose/up` of `model-sg-glm53-w4afp8-tp2-r2b` with the same tag and `file: prod/GLM-5.3-Flash-SGL-TP4-W4AFP8-LongContext.yaml` (the long fleet file), `dry_run` first. The same one-replica rule applies.
